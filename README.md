# Языковые модели в игре «Ультиматум»

Программа проводит эксперимент по проекту: решения отвечающего (I), раскрытие языка (II), прогнозы принятия (III) и дополнительный выбор языка сообщения (IV). Данные сохраняются в локальную базу SQLite. Утилита анализа строит таблицы, графики и оценки из проекта.

Текущая конфигурация использует **GPT‑6 Luna, Qwen3.5‑Flash и Hy4 Flash** через обычный API OpenRouter. На этапах I–III участвуют все три модели. Этап IV проводится на Luna и Hy4. Объём заданий остаётся прежним.

См. `ПРОВЕРКА_ЗАПУСКА.md` для результатов пилота и оценки длительности и расходов полной серии.

Пилот и имитация — это проверки программы, а не результаты исследования. Перед основной серией проверьте протокол, инструкции, доступность моделей, цены и параметры. Прогнозный запрос этапа III в исходном тексте задан не полностью: его реализованная версия находится в `lg_game/prompts.py` и требует проверки автором.

## Установка на macOS

Нужны Python 3 и доступ в интернет для установки библиотек анализа. Дважды откройте `setup.command` или выполните в терминале из папки проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-analysis.txt
```

Проведение игр использует стандартную библиотеку Python; дополнительные библиотеки нужны для анализа и графиков. Команды ниже запускаются в Терминале **из этой папки**. Чтобы перейти в неё, наберите `cd ` и перетащите папку проекта в окно Терминала, затем нажмите Enter.

## Проверка без интернета и оплаты

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m lg_game generate --db data/mock.sqlite --preset pilot --seed 42
.venv/bin/python -m lg_game run --db data/mock.sqlite --budget 0 --mock
.venv/bin/python -m lg_game export --db data/mock.sqlite --out data/mock.csv
.venv/bin/python analysis.py data/mock.csv --output results/mock --bootstrap 100
```

`--mock` создаёт искусственные ответы. Никогда не используйте одну базу и для имитации, и для реального исследования. При повторении примера выберите новое имя базы: существующая база намеренно не перезаписывается.

## Платный пилот

Создайте отдельную базу и укажите ключ в текущем окне терминала. Ввод ключа будет скрыт и не попадёт в историю команд. Ключ не записывается в конфигурацию и базу:

```bash
read -s OPENROUTER_API_KEY
export OPENROUTER_API_KEY
.venv/bin/python -m lg_game generate --db data/pilot.sqlite --preset pilot --seed 42
.venv/bin/python -m lg_game run --db data/pilot.sqlite --budget 0.03 --max-requests 12
.venv/bin/python -m lg_game status --db data/pilot.sqlite
.venv/bin/python -m lg_game export --db data/pilot.sqlite --out data/pilot.csv
.venv/bin/python analysis.py data/pilot.csv --output results/pilot --bootstrap 100
unset OPENROUTER_API_KEY
```

После команды `read` вставьте ключ и нажмите Enter; символы не будут отображаться. `--max-requests` ограничивает число отправок в данном запуске. Для выбора отдельных моделей и этапов предусмотрены, например, `--model qwen --stage I`; см. `python -m lg_game run --help`.

`--budget` — суммарный учтённый лимит **конкретной базы**, а не всего аккаунта. Перед отправкой программа резервирует оценку расхода, затем учитывает стоимость из ответа, если она доступна. При потере ответа фактическое списание может быть неизвестно; цены могут меняться, а параллельные вызовы вне программы не учитываются. Поэтому локальный лимит не является гарантией выставленного счёта. Дополнительно используйте лимит ключа OpenRouter и запас. Все суммы — в долларах США.

## Основной эксперимент

На macOS откройте `run_full.command` или выполните `./run_full.command` из Терминала. Введите суммарный лимит для серии и ключ OpenRouter. Скрипт создаст `data/main_luna_qwen_hy4.sqlite`, покажет прогресс примерно каждые 30 секунд, а по окончании сохранит CSV и рассчитает анализ. Пока идёт сбор, `caffeinate -i` удерживает Mac от автоматического сна. Держите крышку ноутбука открытой и подключите питание.

Если эксперимент остановился на ошибке API или достиг лимита, скрипт сообщит причину. После её устранения повторно откройте `run_full.command`. Скрипт продолжит с той же базой. Лимит включает ранее записанный расход. Завершённые запросы не повторяются. Если программа прервана посреди запроса, его исход остаётся техническим пропуском.

В полном расписании 7 200 назначений: 2 700 решений I, 3 000 матчей II, 600 запросов III и 900 матчей IV. При корректных предложениях программа отправит до 11 100 запросов. Команды для ручного запуска:

```bash
.venv/bin/python -m lg_game generate --db data/main_luna_qwen_hy4.sqlite --preset full --seed 20261119
read -s OPENROUTER_API_KEY
export OPENROUTER_API_KEY
caffeinate -i .venv/bin/python -m lg_game run --db data/main_luna_qwen_hy4.sqlite --budget 0.40
unset OPENROUTER_API_KEY
```

`0.40` — пример ограничения, а не обещание, что его хватит на полную серию. По ходу работы можно открыть второй терминал и посмотреть состояние командой `.venv/bin/python -m lg_game status --db data/main_luna_qwen_hy4.sqlite`. Для выгрузки используйте подкоманду `export`, как в примере пилота.

Модели и тарифы на момент проверки указаны в `config/models.json`. Для каждой модели закреплён провайдер и отключён режим reasoning. Для Luna `temperature` опущена, поскольку выбранный маршрут её не поддерживает. Снимок конфигурации и хеши инструкций и разборщика сохраняются при создании базы. После изменения экспериментальных инструкций создайте новую базу. Старые базы доступны для просмотра и экспорта.

Сырые запросы, ответы и попытки находятся в таблице `attempts` базы SQLite; назначенные задания, разобранные действия и выплаты — в `tasks`. CSV после `export` содержит и незавершённые задания. Некорректный формат, ошибка запроса и корректный игровой отказ различаются. При диагностике и публикации данных не добавляйте в них API-ключи.

Для прогнозов принимаются девять чисел в полном ответе либо в его последней непустой строке, в том числе обрамлённой `**`. На этапе IV инструкция просит вывести сумму и язык одной строкой через запятую. Разборщик также принимает вариант с английским словом `points`. Некорректные ответы автоматически не перегенерируются. Игровой отказ `0` считается корректным ответом.

## Результаты и ограничения

Анализ пишет CSV и графики в папку из `--output`. Таблицы включают частоты принятия, четыре средних этапа II, основные контрасты и доверительные интервалы при достаточном разбросе, границы при пропущенных исходах, сравнение прогнозов и описательные результаты этапа IV. Пояснения и ограничения записываются в `README_analysis.md` внутри папки результатов.

Автоматические результаты не заменяют самостоятельную проверку проекта, гипотез, источников и выбора статистического теста для этапа IV. Повторные запросы характеризуют выбранные модели и инструкции, а не выборку людей. Отсутствие данных не означает нулевого эффекта.
